### 6단계: node-schedule을 사용한 알람 스케줄링 (Server)
`scheduleAlarmById` 함수에서 node-schedule에 알람 작업을 등록:

```ts
// libs/server/alarmScheduler.ts
export async function scheduleAlarmById(alarmId: number, baseUrl: string) {
  const alarm = await client.alarmSetting.findUnique({
    where: { id: alarmId },
    include: { chatMeetup: true },
  });
  
  if (
    alarm &&
    alarm.alarmTime &&
    alarm.status === AlarmStatus.SCHEDULED &&
    alarm.triggerAt > new Date()
  ) {
    scheduleAlarm(alarm, baseUrl);
    return true;
  }
  return false;
}

export function scheduleAlarm(alarm: any, baseUrl: string) {
  if (!alarm.alarmTime) return;
  
  // 기존 작업이 있다면 취소
  if (activeJobs.has(alarm.id)) {
    activeJobs.get(alarm.id).cancel();
  }
  
  const job = schedule.scheduleJob(alarm.triggerAt, async function() {
    try {
      // AlarmSetting 업데이트: status를 SENT로 변경
      const updatedAlarm = await client.alarmSetting.update({
        where: { id: alarm.id },
        data: { status: AlarmStatus.SENT },
        include: {
          // ...include options...
        },
      });

      // 알람 트리거 API 호출
      const response = await axios.post(`${baseUrl}/api/alarm/trigger`, {
        alarmId: alarm.id
      });
      
      // 작업 완료 후 Map에서 제거
      activeJobs.delete(alarm.id);
    } catch (error) {
      console.error(`Error triggering alarm ID ${alarm.id}:`, error);
    }
  });
  
  // 활성 작업 Map에 추가
  activeJobs.set(alarm.id, job);
}
```

### 8단계: 사용자 브라우저에 web-push 알림 표시 (Client)
web-push 라이브러리를 통해 사용자 브라우저에 알림이 표시됨:

```ts
// libs/server/pushService.ts
export async function sendPushNotification(userId: number, payload: any) {
  try {
    // 사용자의 푸시 구독 정보 조회
    const user = await client.user.findUnique({
      where: { id: userId },
      select: { pushSubscription: true }
    });
    
    if (!user?.pushSubscription) return false;
    
    const subscription = JSON.parse(user.pushSubscription);
    
    // web-push를 사용해 알림 전송
    await webpush.sendNotification(
      subscription,
      JSON.stringify(payload)
    );
    
    return { sent: true };
  } catch (error) {
    console.error('Push notification sending failed:', error);
    return { sent: false, error };
  }
}
```

## 워크플로우 평가

### 강점
1. **트랜잭션 처리**: 약속과 메시지 생성이 트랜잭션으로 처리되어 데이터 일관성 보장
2. **에러 처리**: 다중 try-catch로 각 단계별 실패 처리 및 사용자 피드백
3. **UTC 시간**: 시간 계산 및 저장 시 UTC 변환으로 시간대 문제 방지
4. **중복 방지**: 기존 알람 취소 후 새로운 알람 등록으로 중복 알림 방지
5. **메모리 관리**: 알람 작업 완료 후 activeJobs에서 제거하여 메모리 누수 방지

### 개선점
1. **타입 안정성**: `scheduleAlarm(alarm: any, ...)` 같은 타입 캐스팅 제거
   ```ts
   interface AlarmWithMeetup {
     id: number;
    alarmTime: string;
     status: AlarmStatus;
     triggerAt: Date;
     chatMeetup: { /* ... */ };
   }
   export function scheduleAlarm(alarm: AlarmWithMeetup, baseUrl: string) { /* ... */ }
   ```

2. **재시도 메커니즘**: web-push 실패 시 재시도 로직 추가
   ```ts
   async function retryPushNotification(userId: number, payload: any, retries = 3): Promise<boolean> {
     for (let i = 0; i < retries; i++) {
       try {
         await sendPushNotification(userId, payload);
         return true;
       } catch (error) {
         console.error(`Push retry ${i+1}/${retries} failed:`, error);
         await new Promise(resolve => setTimeout(resolve, 1000));
       }
     }
     return false;
   }
   ```

3. **서버 재시작 대비**: 서버 시작 시 스케줄된 알람 복구 로직 추가
   ```ts
   // server.js 또는 app 초기화 코드
   import { loadAndRescheduleAlarms } from '@libs/server/alarmScheduler';
   
   app.listen(PORT, async () => {
     console.log(`Server running on port ${PORT}`);
     const rescheduledCount = await loadAndRescheduleAlarms(`https://${HOST}`);
     console.log(`Rescheduled ${rescheduledCount} alarms`);
   });
   ```

4. **동시성 제어**: 알람 변경/취소/생성 작업을 트랜잭션으로 처리하여 race condition 방지
   ```ts
   await client.$transaction(async (tx) => {
     // 기존 알람 취소 및 새 알람 생성을 하나의 트랜잭션으로
   });
   ```

5. **로깅 개선**: 문제 추적을 위한 구조화된 로깅 추가
   ```ts
   const logger = {
     info: (message, data = {}) => console.log(JSON.stringify({ level: 'info', message, ...data, timestamp: new Date().toISOString() })),
     error: (message, error, data = {}) => console.error(JSON.stringify({ level: 'error', message, error: error.toString(), stack: error.stack, ...data, timestamp: new Date().toISOString() }))
   };
   ```

## 결론

전체적으로 워크플로우는 잘 설계되어 있고 순차적으로 적절히 실행됩니다. 약속 생성부터 알림 전송까지 각 단계가 분리되어 있으면서도 잘 연결되어 있습니다. 위 개선점들을 적용하면 더욱 견고한 시스템으로 업그레이드될 것입니다.
