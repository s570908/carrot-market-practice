# 웹 푸시 알림 시스템 상세 흐름도

## 1. 시스템 구성요소

```
+----------------+    +----------------+    +----------------+
| User Agent     |    | Web Server     |    | Push Service   |
| (Browser)      |    | (Application)  |    | (FCM/Mozilla)  |
+-------+--------+    +-------+--------+    +-------+--------+
        ^                     ^                     ^
        |                     |                     |
        v                     v                     v
+----------------+            |                     |
| Service Worker |<-----------+---------------------+
+----------------+
```

## 2. VAPID 키 생성 및 설정

```
+----------------+
| Web Server     |
+-------+--------+
        |
        | 1. 공개/비공개 키 쌍 생성 (ECDSA P-256 알고리즘 사용)
        v
+------------------+
| VAPID Keys       |
| - Public Key     | → 웹 푸시 서비스가 메시지 발신자 식별/인증에 사용
| - Private Key    | → 웹 서버가 JWT 토큰 서명에 사용
+------------------+
        |
        | 2. 키 저장 및 웹 앱에 공개키 제공
        v
+------------------+
| Web Application  |
| (Client-side)    |
+------------------+
```

**VAPID 키 상세 설명**:

- **용도**: 애플리케이션 서버가 푸시 서비스에 자신을 인증하고 신원을 증명
- **알고리즘**: ECDSA(Elliptic Curve Digital Signature Algorithm) P-256 사용
- **비공개키 관리**: 서버에 안전하게 보관, 절대 클라이언트에 노출되면 안 됨
- **공개키 사용**: 구독 과정에서 `applicationServerKey`로 전달됨

         |                      |  3.1 options에 applicationServerKey(VAPID 공개키)

         |                      |                                            |

**3.2 endpoint URL 및 키 생성 상세 설명**:

### Endpoint URL 설명

- **생성 주체**: 푸시 서비스(FCM, Mozilla 등)
- **내용**: 특정 브라우저-애플리케이션 쌍을 고유하게 식별하는 URL
- **형식**: `https://[푸시서비스도메인]/[고유식별자]` (예: `https://fcm.googleapis.com/fcm/send/dJUzZ7...`)
- **용도**:
  - 애플리케이션 서버가 푸시 메시지를 보낼 대상 주소로 사용
  - 특정 사용자의 특정 브라우저 인스턴스를 가리키는 고유 식별자
- **특징**:
  - 구독마다 고유하며 재사용 불가
  - 보안상 추측 불가능한 형태로 생성됨
  - 서버는 이 URL로 HTTP 요청을 보내 푸시 알림 전송

### 클라이언트 키 상세 설명

브라우저에서 생성되는 두 종류의 키:

1. **p256dh (클라이언트 공개키)**

   - **용도**: 푸시 메시지 암호화에 사용
   - **알고리즘**: ECDH(Elliptic Curve Diffie-Hellman) P-256
   - **길이**: 일반적으로 65바이트
   - **작동 방식**:
     - 서버는 이 키로 페이로드를 암호화
     - 오직 구독 브라우저만 해독 가능
     - 푸시 서비스도 메시지 내용을 볼 수 없음
   - **중요성**: 중간자 공격 방지 및 메시지 기밀성 유지

2. **auth (인증 비밀)**
   - **용도**: 추가 인증 및 메시지 무결성 보장
   - **형태**: 16바이트 랜덤 비밀 값
   - **작동 방식**:
     - 메시지 암호화 과정에서 솔트(salt)와 함께 사용
     - HMAC 키로 활용되어 메시지 인증에 기여
   - **중요성**:
     - 무작위 푸시 메시지 방지
     - 권한 없는 발신자로부터 보호

## 4. 푸시 메시지 전송 및 처리 흐름

```
+----------------+    +----------------+    +----------------+    +----------------+
| Web Server     |    | Push Service   |    | User Agent     |    | Service Worker |
| (Application)  |    |                |    | (Browser)      |    |                |
+-------+--------+    +-------+--------+    +-------+--------+    +-------+--------+
        |                     |                     |                     |
        | 1. 푸시 알림 트리거   |                     |                     |
        |                     |                     |                     |
        | 2. JWT 토큰 생성     |                     |                     |
        | 2.1 헤더: {"typ":"JWT", "alg":"ES256"}     |                     |
        | 2.2 페이로드: {                            |                     |
        |   "aud": "푸시서비스URL",                   |                     |
        |   "exp": 만료시간,                         |                     |
        |   "sub": "mailto:관리자@도메인.com"         |                     |
        | }                                         |                     |
        | 2.3 VAPID 비공개키로 서명                   |                     |
        |                     |                     |                     |
        | 3. 메시지 암호화 (p256dh 키로)              |                      |
        | 4. 암호화된 메시지 + 인증 헤더 전송           |                     |
        +-------------------->|                     |                     |
        |                     |                     |                     |
        |                     | 5. JWT 검증          |                     |
        |                     | 5.1 서명 검증(VAPID 공개키 사용)             |
        |                     | 5.2 만료 시간 및 대상(aud) 확인              |
        |                     |                     |                     |
        |                     | 6. 푸시 메시지 전달    |                     |
        |                     | (암호화된 상태 그대로) |                     |
        |                     +-------------------->|                     |
        |                     |                     |                     |
        |                     |                     | 7. 서비스 워커 깨우기   |
        |                     |                     +-------------------->|
        |                     |                     |                     |
        |                     |                     |                     | 8. 'push' 이벤트 발생
        |                     |                     |                     | 9. p256dh/auth 키로 메시지 복호화
        |                     |                     |                     |
        |                     |                     |                     | 10. showNotification() 호출
        |                     |                     |<--------------------+
        |                     |                     |                     |
        |                     |                     | 11. 사용자에게 알림 표시 |
        |                     |                     |                     |
```

**메시지 암호화 및 전송 상세 과정**:

1. **메시지 암호화**:

   - ECDH + AES128-GCM 암호화 알고리즘 사용
   - 클라이언트 공개키(p256dh)로 암호화 키 생성
   - auth 비밀을 사용하여 추가 인증 레이어 적용
   - 16바이트 솔트(salt) 생성하여 암호화 강화

2. **HTTP 요청 구성**:

   - Method: POST
   - URL: PushSubscription.endpoint
   - Headers:
     - `Authorization: vapid t=[JWT토큰],k=[VAPID공개키]`
     - `Content-Type: application/octet-stream`
     - `Content-Encoding: aes128gcm`
     - `TTL: [초단위만료시간]` (예: 2419200 = 4주)
   - Body: 암호화된 푸시 메시지

3. **푸시 서비스 역할**:

   - JWT 토큰 검증 (발신자 인증)
   - 메시지 큐잉 (브라우저가 오프라인일 경우)
   - TTL 기반 만료 처리
   - 대상 브라우저로 암호화된 메시지 전달 (내용 확인 불가)

4. **서비스 워커 처리 과정**:
   - push 이벤트 수신 및 처리
   - 암호화된 메시지 자동 복호화 (브라우저 내부적으로 처리)
   - 알림 표시 또는 백그라운드 작업 수행

## 8. 전체 흐름 요약 및 주요 보안 포인트

1. **VAPID 키 단계**:

   - 서버 측에서 ECDSA P-256 키 쌍 생성
   - 비공개키는 서버에 안전하게 보관
   - 공개키는 클라이언트 구독 과정에 사용

2. **구독 단계**:

   - 사용자 권한 획득 후 PushManager.subscribe() 호출
   - VAPID 공개키를 applicationServerKey로 제공
   - 푸시 서비스가 endpoint URL 생성
   - 브라우저가 p256dh와 auth 키 생성
   - 구독 정보를 서버에 저장

3. **푸시 메시지 전송 단계**:

   - 서버가 JWT 생성 및 VAPID 비공개키로 서명
   - 메시지 내용을 p256dh 키로 암호화
   - 인증 헤더와 암호화된 메시지를 푸시 서비스로 전송
   - 푸시 서비스는 JWT 검증 후 메시지 전달
   - 브라우저는 자체 키로 메시지 복호화
   - 서비스 워커가 알림 표시

4. **보안 중요 포인트**:
   - **엔드-투-엔드 암호화**: 푸시 서비스도 메시지 내용을 볼 수 없음
   - **다중 인증 레이어**: VAPID, Endpoint URL, p256dh, auth로 보안 강화
   - **제한된 수명**: JWT 토큰과 푸시 메시지에 TTL 적용
   - **명시적 권한**: 사용자 허가 없이는 푸시 메시지 수신 불가
   - **암호학적 무결성**: 중간자 공격 및 위변조 방지

이 흐름도는 웹 푸시 알림의 핵심 메커니즘을 보여주며, 특히 endpoint URL과 키 생성 과정의 보안적 중요성을 강조합니다. 각 구성 요소는 상호 연결되어 안전한 푸시 메시지 전달을 보장합니다.
